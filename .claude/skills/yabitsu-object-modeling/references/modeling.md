# 写真からBlenderで立体を作る

## 観察と分解

全景だけで判断せず、対象を拡大して外周、左右非対称、厚さ、継ぎ目、足元を見る。人物・既知寸法の標識・階段などを尺度にできても、写真の透視で誤差があるため推定値とする。複数視点がない場合に、完全な実測モデルとは呼ばない。

Googleマップの画面がWeb検索ツールで取得できない場合は、利用できるブラウザツールでユーザーのURLを開き、画面を確認・撮影する。thumbnail APIは必須経路にしない。画面上に重なる道路名やUIを実物の文字として作らない。写真を切り抜いた比較でも出典表示を保つ。

| 対象 | 主な形状と分け方 |
|---|---|
| 自然石の石碑 | 正面の不規則な外周、厚み、削った平面、凹部、台座を別々に考える |
| 金属看板 | 板厚、折り返し、枠、支柱、留め具を形状にし、読める文字を自作画像か文字メッシュにする |
| 石積み・擁壁 | 壁全体の線、傾斜、段差を先に合わせ、その上へ実寸の石や目地を置く |
| 手すり・欄干 | 柱の間隔・径・高さ、斜面に沿う横材を組む。断面を角柱へ置換した場合は差として残す |

## 不規則な外周と浅い凹部

正面をXZ平面、正面方向を−Yとして外周点列を作り、奥行き方向へ押し出す。厚さのある石碑では、裏面と側面も張って閉じる。単位と軸は既存モデルがある場合はそれに合わせる。

Booleanのカッター同士が同一平面で接すると、重複面・穴・大部分の消失が起きる場合がある。失敗したらメッシュを見ずにカッターの値だけ振り続けない。適切な隙間を残すか、次の方法で凹部を直接作る。

1. 外周と、角を丸めた長方形などの凹部輪郭を2Dで定義する。
2. 輪郭の辺を拘束として `mathutils.geometry.delaunay_2d_cdt` へ渡す。`output_type=0`の結果から、重心が外周の外・凹部の内側にある三角形を除く。出力頂点の並びが変わるため`orig_verts`で対応付ける。
3. 残る面を前面の深さへ、凹部の輪郭の複製を奥の深さへ置く。両輪郭を側面でつなぎ、凹部底も張る。
4. 外周から裏面への側面を張り、`bmesh.ops.recalc_face_normals`。適度なBevelを加える。
5. **非多様体辺が0でも、空のメッシュやわずかな残片は合格ではない。** 面数、寸法、想定範囲の体積、実レンダーを一緒に確認する。

薄い看板にはこの凹部構造を無理に適用しない。小さい留め具など、見た目に影響しない細部はゲーム用に簡略化できる。

## 材質と文字

- 石の大きな色むら、細粒、凹凸を異なるスケールのNoiseとBumpで分ける。全体を大きなBumpで砂状にしない。雨染みは上から下の流れ、苔・地衣類は面の位置と湿りやすい場所に沿わせる。
- 日本語UIでは既定ノード名が翻訳される。`nodes['Principled BSDF']`に依存せず、型で探す。ノードがない場合は用途に必要なものを明示作成する。

```python
bsdf = next((n for n in material.node_tree.nodes
             if n.type == 'BSDF_PRINCIPLED'), None)
if bsdf is None:
    bsdf = material.node_tree.nodes.new('ShaderNodeBsdfPrincipled')
    # 新規作成時は既存の出力ノードと接続する。
```

- 日本語フォントは実在するパスを調べる。Blender同梱PythonにPillow等があると仮定しない。モデル保存後にフォント・画像の依存先を確認する。
- 題字は読めた文字だけ再現する。本文が読めない場合、ぼかした面や抽象的な刻みなど、外観を近似した旨をモデル情報にも残す。漢字や歴史的文章をランダムに作らない。
- 面に重ねる文字・地衣類が空中や凹部に浮かないよう、対象面へray_castして位置を決める。重なった面はゲーム向けベイクでまとめ、ちらつきを避ける。

## ライブ表示とヘッドレス処理

使用できるMCP・GUIツールを先に確認する。Blender専用MCPが接続済みなら、まずファイル名とシーンを読み、既存作業を壊さずに操作する。ユーザーが手で操作している間は同時入力しない。

- 専用MCPに形状操作がなければ、Python実行機能で`bpy`の処理を送る。シーン全体を不用意に初期化せず、新規シーンやコレクションへ作る。
- MCPが未接続なら、既に導入済みのBlenderライブ操作スキル・アドオンの起動方法を読む。専用MCPもライブブリッジもなければ、利用可能なGUIツールのAPIで起動・接続を設定する。接続できなかったら理由を報告し、「途中を表示した」とは言わない。
- Macの`open -n -a /Applications/Blender.app`は別インスタンスを開く場合の例。ヘッドレスの検証は、実在するBlender実行ファイルに`-b`、`--python-exit-code 1`、`--python`を渡す。起動エラー時は結果を読み、アプリの場所と権限を確認する。
- 長いスクリプトはファイルへ保存し、輪郭・文字・質感のような段階に分けて実行する。送った操作の直後は画面が再描画前の場合があるので、次の画面取得で実際の変化を確かめる。
- ライブでモデルを作るだけなら最終レンダーを毎回実行しない。ビューポートでまとまった修正を確認し、重い描画は仕上げ時に行う。

カメラ・表示には対象を収める。地面や撮影用の背景をフレーミングの対象にすると、モデルが極端に小さくなる。配色は実使用の照明・色管理に依存するため、AgXやStandardの一方を全案件に強制しない。

## 保存した実物の検証

同梱`check_asset.py`はアクティブなシーンと指定コレクションを読み取り、評価後のメッシュを検査する。元blendは変更しない。

- 空・非有限座標・面積0の形状を検出する。存在すべき主要部品は`--require <名前の先頭>`で指定し、看板・台座だけが欠落した場合も検出する。JSONの`required_matches`で各指定に何が一致したか確認する。
- `--closed <名前の先頭>`で閉じた本体を指定した場合、非多様体辺・体積も確認する。対象名が見つからない場合も失敗する。
- `--min-volume`・`--min-height`は予定寸法から設定する。小さな破片だけが残った失敗を検出するために使う。薄板などに同じ閾値を使わない。
- 正面・側面・背面・真上・斜めの画像を実際に開き、文字の向き、凹部、浮き、突き抜け、カメラに隠れた欠けを確認する。対象が見えていることと、写真と一致することは別に検証する。

## 石碑の実例を使う場合

`assets/landmarks/asama_monument/sengen_monument.blend`と同じ場所の`asset.json`を確認する。`export/compare/asama/monument_preview.png`・`monument_views.jpg`・`monument_reference_comparison.jpg`が比較資料。実例の本体は不規則な外周と二つの凹部、二段の台座を持つ。寸法・背面・書体は近似で、本文は未判読。実例の寸法や本文密度を、別のオブジェクトの仕様にしない。
