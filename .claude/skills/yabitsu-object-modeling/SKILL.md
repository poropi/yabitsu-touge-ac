# ヤビツ峠のオブジェクト制作

写真から**輪郭・立体構造・寸法比**を取り出してモデル化する。写真を板に貼っただけで立体の再現に代えない。対象は石碑に限定せず、看板、石積み、欄干、設備などにも適用する。

## 最初に読むもの

プロジェクトのルートを作業ディレクトリにする。`git status --short` で既存変更を確認し、依頼された対象だけ扱う。`assets/landmarks/`、対応する `data/manual/`、`yabitsu/*_area.py`、`scripts/track_build_manifest.py` を調べ、先行モデル・配置・変換器を再利用する。

- 形を作る前：[references/modeling.md](references/modeling.md)。輪郭からの立体化、彫り込み、文字、材質、ライブ制作の注意点。
- AC用の変換・配置を頼まれたとき：[references/assetto-corsa.md](references/assetto-corsa.md)。座標、UV、ベイク、衝突、既存の変換経路。
- 寸法や文字が不明なら、一次資料や別視点を調べる。解決できなかった部分は推定として残す。無料・自作の素材を使う。

## 制作の進め方

1. 写真・ストリートビューのURL、panoid、撮影年月、画角・向き、見える部品を記録する。読み取れない碑文・看板の文章を創作しない。参照画像は比較用とし、貼り付け素材へ転用しない。
2. 主役の外形、段差、厚さ、部品同士の位置を先に作り、基準画像と比較する。石の粒、染み、苔などは形が合ってから加える。未実測の数値を実測値と呼ばない。
3. ユーザーが過程を見たい場合はGUIのBlenderへ接続して、輪郭と台座、彫り込みと文字、質感の各段階を実際に表示する。裏で一括生成して最後の画像だけ見せる方法に置き換えない。ライブ操作の具体手段はmodeling.mdを参照。
4. 本体・台座・文字・装飾と撮影用地面・照明・カメラを別コレクションにする。メートル単位、上方向と正面方向を記録する。既存blendは別名保存する。
5. 正面・左右側面・背面・真上・斜めを確認し、写真と同じ向きでも並べる。配置を直した場合は、真上の写真と真上のモデルを位置合わせして重ねる。見えない背面の確認画像は「推定」と表示する。
6. 保存したblendを別プロセスで読み直す。下のヘルパーで対象が消えていないか、形状・寸法・体積を検査し、完成画像も目視する。数値合格だけで写真との一致を主張しない。

## 保存先と依頼の範囲

| 内容 | プロジェクト内の場所 |
|---|---|
| 制作元blend、使用した自作テクスチャ、asset.json | `assets/landmarks/<asset-id>/` |
| 再生成用のBlenderスクリプト | `blender_scripts/` |
| 一時作業、元写真、途中・完成・比較・検証結果 | `export/compare/<site-id>/`（作業用はその下の`work/`） |
| ベイク画像、ゲーム用NPZなど再生成できる中間物 | `data/processed/landmarks/<asset-id>/` |
| コース内の位置・向き・接地・当たり判定の設定 | 既存の`data/manual/`と`yabitsu/`の読取側に合わせる |

`asset.json`には制作元、軸・単位、寸法の根拠、参照画像の場所、未再現部分、ベイク・ゲーム反映の実施状況を書く。Google等の参照画像を制作元・配布アセットに含めない。

「フォルダに置く」は保存・配置・コピー検証まで。「ゲームへ組み込む」は変換・材質登録・既存の仮形状の置換・座標と接地の検証まで。依頼が組み込みを含むなら素材のコピーだけで止めない。単体制作や配置だけなら、全コースの再生成やゲームへのインストールを追加しない。

## 同梱の形状チェック

`SKILL`はプロジェクトルートからのパス。Claude側の入口から読んでも同じコマンドを使える。Blender実行ファイルは現在のOSの実在パスを使う。以下はmacOS例。

```sh
SKILL=.agents/skills/yabitsu-object-modeling
blender -b assets/landmarks/asama_monument/sengen_monument.blend --python-exit-code 1 --python "$SKILL/scripts/check_asset.py" -- --collection '01 ' --closed '石碑本体' --require '上段' --require '下段' --require '碑文面' --require '上部の横額' --min-volume 0.5 --out "$PWD/export/compare/asama/monument_check.json"
```

`0.5`はこの石碑を確認するための下限の例。ほかの対象では予定寸法から適切に決める。予定している主要部品は`--require`で存在確認する。薄板・葉・草に閉じた立体や体積を要求しない。`--help`で引数を確認する。

報告には制作元、見られる完成・比較画像、写真との差、未確認の理由、ゲーム反映の段階を含める。小さな単体制作を大量の並列モデル制作へ広げない。
