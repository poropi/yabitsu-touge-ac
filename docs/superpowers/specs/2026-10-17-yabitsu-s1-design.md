# ヤビツ峠 再現コース 設計書（全体構成 ＋ S1 試作区間）

- 作成日：2026-10-17
- 対象ゲーム：Assetto Corsa（Content Manager ＋ Custom Shaders Patch 環境）
- 状態：レビュー待ち

---

## 1. 目的

神奈川県のヤビツ峠（県道70号 秦野清川線）を、Assetto Corsa 用のコースとして**一から作り直し**、**実際の道をできるだけ正確に再現する**。

- 重視すること：道の線形・高低差・道幅の正確さ（走りやすさや配布より優先）
- 作り方：公開データ（国土地理院・OpenStreetMap）からスクリプトで自動生成し、写真資料と見比べて補正する

## 2. 前提と制約

| 項目 | 内容 |
|---|---|
| 既存コース | `content/tracks/nanohanadai`（mitchan38 氏・masaboo 氏作）は**一切変更しない**。素材（モデル・テクスチャ）も流用しない。走り比べの参考として見るだけ |
| 権利 | 素材は自作または自由利用できるものだけを使う。ストリートビュー等の写真はテクスチャに使わず、見比べの参考のみ |
| 出典表記 | 国土地理院（標高タイル・空中写真）と OpenStreetMap（© OpenStreetMap contributors, ODbL）の出典をコースの `read_me` と `ui_track.json` に記載する |
| 作業分担 | Claude：データ取得・加工、Blender スクリプトによる生成、AC 設定ファイル作成。ユーザー：見た目の確認、ksEditor での書き出し、走行テスト（手順は Claude が案内） |
| ユーザーの経験 | Blender・コース制作ともほぼ初めて。操作は一つずつ案内する |

## 3. 全体構成

### 3.1 区間分割

峠全体を5区間に分け、区間ごとに「作る → 走る → 直す」を完結させる。

| 区間 | 範囲 | 位置づけ |
|---|---|---|
| **S1** | 菜の花台 → ヤビツ峠（山頂） | **試作区間**。作業の流れ（パイプライン）を確立する。本書の詳細設計の対象 |
| S2 | 蓑毛 → 菜の花台 | 秦野側の下半分（既存MODが再現している約1.25kmはこの上部に当たる） |
| S3 | 名古木 → 蓑毛 | 市街地寄りで建物が多い。最後に回すか、省略を検討 |
| S4 | ヤビツ峠 → 札掛 | 清川側。狭い林道 |
| S5 | 札掛 → 宮ヶ瀬 | 清川側の終点まで |

S2 以降は、S1 で確立したパイプラインを再利用する。各区間は S1 完了後に、個別に設計を見直してから着手する。

### 3.2 座標系（全区間共通・最初に固定）

- 平面座標：**JGD2011 平面直角座標系 第IX系（EPSG:6677）**、単位はメートル
- 水平方向の原点：**ヤビツ峠**（OSM の峠ノード 北緯35.42782°、東経139.21934°）を (0, 0) とする
- 高さ：**標高そのまま**（メートル）。原点で高さを引かない
- Blender 内：X = 東、Y = 北、Z = 標高、1 Blender単位 = 1m
- AC へは FBX 書き出し時に Y-up へ変換する（具体的な書き出し設定は実装計画で決める）

すべての区間をこの座標で作るため、別々に作った区間がそのままつながる。

| # | 工程 | 担当 | 成果物 |
|---|---|---|---|

| 2 | 中心線の整形：座標変換、空中写真に合わせた位置補正、なめらか化。標高を中心線に沿って取得し、平滑化 | Claude（位置補正は空中写真を見ながら一緒に確認） | 中心線データ（位置・標高・道幅・路面の傾き） |

| 4 | 当たり判定：AC の命名規則（`1ROAD`、`1GRASS`、`1WALL` など）に沿った物理用の面 | Claude | `.blend` 内の物理用オブジェクト |

## 4. S1 詳細設計（菜の花台 → ヤビツ峠）

### 4.1 実測データ（2026-10-17 時点の OSM ＋ 国土地理院 dem5a）

| 項目 | 値 |
|---|---|
| 区間 | 菜の花台駐車場前 → ヤビツ峠 |
| 長さ | 約 3.3km（3,281m） |
| 標高 | 562m → 760m（+198m） |
| 平均勾配 | 約 6.1% |
| カーブ | 曲がった角度の合計 約 3,070°。半径30m未満の急カーブを含む（ヘアピンあり） |
| 車線（OSM） | 1車線 約 2.3km ／ 2車線 約 1.0km（橋 約 10m を含む） |
| 標高データの注意 | 生データでは最大33%の勾配が出る（切り土・盛り土を拾うため）。平滑化が必須 |

### 4.2 作るもの

1. **路面**
   - 道幅は区間ごとに設定する。初期値は OSM の車線数から仮に置き、空中写真で道の端を測って正しい値に直す
   - 路面の傾き：カーブの傾斜（片勾配）と、直線の水はけ用の傾斜
   - 中央線（2車線区間）と外側線、側溝
2. **道の位置補正**：国土地理院の空中写真を Blender の下敷きにし、道の端に中心線を合わせる（写真は位置合わせ専用。テクスチャには使わない）
3. **地形**
   - 中心線から左右約100m：5mメッシュ（dem5a）で細かく作る
   - その外側から約2km先まで：10mメッシュ（dem10b）で粗く作り、遠くの山並みにする
   - 道と地形のつなぎ目は、切り土・盛り土の法面としてなめらかにつなぐ
4. **擁壁・ガードレール**：ストリートビューで場所を確認し、ユーザーと一緒に「どこからどこまで、左右どちらに何があるか」の一覧を作って配置する
5. **木**：軽い板状の木を、地形の斜面に自動で並べる（道路上や擁壁の位置には置かない）
6. **始点・終点**：菜の花台駐車場とヤビツ峠の駐車場を簡単な形で作る
7. **AC 用の要素**
   - レイアウトは2つ：`s1_up`（菜の花台 → 山頂）、`s1_down`（山頂 → 菜の花台）
   - 各レイアウトとも、始点側の駐車場にピット4台分とスタート位置4台分を置く
   - スタートとゴールが別の場所になる計測（`AC_OPEN_START` ／ `AC_OPEN_FINISH`）
   - `surfaces.ini`：路面（ROAD）、草・路肩（GRASS）、壁（WALL）を定義する
   - リプレイ用カメラ、ミニマップ、`ui_track.json`（出典表記を含む）

### 4.3 S1 では作らないもの（後の段階に回す）

- 建物の作り込み（レストハウスなどは箱形で仮置き）
- 標識・カーブミラーなどの細かい再現
- CSP の設定（夜間照明・雨など）、音
- 高品質な木のモデル

### 4.4 完成の条件（受け入れ基準）

| 観点 | 基準 |
|---|---|
| 道の位置 | 空中写真の道の中心と、およそ2m以内でずれていない |
| 高さ | 道の中心の高さが、標高データ（平滑化前）と ±1.5m 以内。橋など標高データが当てにならない場所は除く |
| 路面 | 走行中に、データ由来の不自然な段差・うねり・突き上げがない |
| 走行 | 上り・下りとも、スタートからゴールまで止まらずに走れ、タイムが計測される。壁やガードレールを車がすり抜けない |
| 動作 | ユーザーの PC で、カクつかずに走れる |
| 見た目 | ストリートビューと見比べて、ユーザーが「違和感がない」と判断する |

### 4.5 確認方法

1. **データ段階**：コースの形・高低差・勾配のグラフを作り、ユーザーに見てもらう
2. **Blender 段階**：画面のスクリーンショットで、道・地形・擁壁を確認してもらう
3. **AC 段階**：上り・下りを走ってもらい、気になった場所をミニマップ上の位置と一緒に報告してもらう。直したら同じ場所をもう一度走って確かめる

## 5. 想定されるリスクと対策

| リスク | 対策 |
|---|---|
| OSM の道路位置・車線数の誤り | 空中写真で位置と道幅を確認・補正する |
| 標高データのノイズ（切り土・橋・木） | 中心線に沿った平滑化。橋の区間は前後の高さから補間する |
| Overpass（OSM のデータ取得サーバー）の混雑 | 取得したデータは `data/raw/` に保存して使い回す。予備のサーバーを使う |
| ksEditor が Blender の FBX を正しく読めない | S1 の最初に、小さな試験用モデルで書き出しを試してから本番に進む |
| kn5 が重くなりすぎる | 遠くの地形と木は粗いモデルにし、サイズと動作を見ながら調整する |
| Blender との接続（MCP） | 作業開始時にユーザーが Blender を起動し、接続を有効にする |
