# ヤビツ峠 全域の森（④ 山の森林化）設計

2026-10-19。Codex が作った「緑のスライム」状の山の森（`export/mountain_water_full/20261019_165208_500967/`、ユーザーが不採用）を作り直す。

## 目的と理由

ユーザーの言葉：「本来はリアルな樹木が生い茂るイメージ」「樹木のパターンを何通りか用意し、今のスライムの軍勢をその樹木に置き換える」「空撮と比較しながら、山の森林のように仕上げて」「S1のみでなく今回のマップ全体」。

森を見る場面は **3つ全部**（ユーザー回答「どちらも」）：

1. 上空から見下ろし、空中写真と見比べる。
2. AC で走りながら、運転席から遠くの山を見る。
3. 車を降りて森の中を歩く（CSP の歩行機能）。そのときに「森にいる」と感じられること。

品質の基準は **S1 の道路沿いの木**（Codex 版 `export/landscape_s1_station_owner_pilot/20261019_151226_498974/` の描画）。ユーザー：「間違っても、おもちゃの木みたいなものはやめてくださいな！」

## やること（ゴール）

- マップ全体（地形がある範囲：遠景地形 `track_terrain_far.npz` の約 7.2 km × 19.7 km）の山を、本物らしい木の森にする。
- **道路脇の木も全部この新しい森に置き換え、道から森の奥まで切れ目なくつなぐ**（ユーザー回答）。今ある板の木（`TREES_*`、道路から 105 m 以内、`yabitsu/trees.py`）は見えなくする。
- 木は何通りかのパターンを用意する。少なくとも杉・檜・広葉樹の3種。それぞれ高さや形の違う複数のパターンを作る。
- 植える場所と樹種は**空中写真に合わせる**。写真で森なら森、畑・草地・町・伐採地なら植えない。濃く細かい樹冠は杉・檜、明るく丸い樹冠は広葉樹、のように写真から読み取る。
- 仕上がりは**空中写真と同じ範囲を並べた比較画像**で確かめる。

## やらないこと

- 湖・川の水面の見た目直し（Codex ④のもう半分）。今回の依頼は森だけ。ただし、水の中・川原・湖面には木を植えない。
- 道路・壁・ガードレール・橋・建物など、森以外の景観の仕上げ。これは森が終わってから別の作業として行う（ユーザー回答）。
- 既存コースファイル（`yabitsu_main/nagoki/s4/s5/kitahara.kn5`）の作り直し。ユーザーは作り直しを禁止している（記憶 feedback-batch-rebuilds）。
- Codex の S1 景観確認レイアウト（`s1_landscape_up/down`、`yabitsu_s1_landscape_test.kn5` 1.6 GB）への組み込み。触らずに残す。消すかどうかは後でユーザーが決める。

## 失敗とみなすこと（技術的に動いても不可）

- おもちゃの木・スライム・緑の塊に見える（近くでも遠くでも）。
- Blender の画面では綺麗でも、**AC の中では**違いが分からない、スカスカ、色が浮く（Codex の S1 で起きたこと）。
- 遠くの簡単な木と近くの細かい木の切り替えが目立つ（近づくと急に別物になる、ポップする）。
- 道路・駐車場・広場・分岐路（バリケードの先も。将来オープンワールドにするため）・建物・町・畑・湖・川の上に木が生える。
- 走る車の正面をふさぐ枝や幹。頭上を覆う枝は、現地写真で覆っている場所なら走行の邪魔にならない範囲で可（ユーザーの以前の指示）。
- 木が地面から浮く、または地面に埋まる。
- AC が重くて走れなくなる。
- ユーザーが見られるまでに、検証ばかりで時間がかかる（Codex への不満：「検証検証・・・って何度検証すればいいんだよ！」）。

## 前提・制約

- ユーザーの PC：RTX 5070、Core i7-14700K、メモリ 64 GB。
- AC には CSP 0.3.0-preview619 が入っている。CSP には大量の木を表示する機能（トラック側の `extension/ext_config.ini` の `[TREES]`、木の一覧 txt、木のパッケージ zip（`tree.ini` ＋ `.mesh`/`.bin` の LOD 0〜2 ＋ dds））がある。例：`content/tracks/hakoneTurnpike_wmmt5/extension/trees/`。`.mesh` の中身の仕様書は手元にない。
- `content/tracks/yabitsu/extension/` は空。ここへ森の設定を足せば、既存 kn5 を作り直さずに済む。古い板の木は `ext_config.ini` のメッシュ非表示設定（`[MESH_ADJUSTMENT_...]` で `TREES_*` を消す。ターンパイクに例あり）で隠す。
- 地面の高さは、DEM ではなく**実際の地形メッシュ**（近景・中景・遠景・町の地面）に合わせる。木が浮いたり埋まったりしないようにするため。
- 植えてはいけない場所の資料は既にある：道路・土台（`track_pads.json`、`track_parking.json`）、町（`nagoki.tree_free_areas`、北原）、建物（`s3_houses` ほか）、湖・川（`yabitsu/water.py`、`s5_water.json`）、分岐路（`side_roads.py`）、トンネル・橋。
- 空中写真：国土地理院のシームレス空中写真（出典表示が必要）。既存コードの `yabitsu/gsi.py` と `yabitsu/photo.py` で取得している。
- 作業は main から切った新しいブランチで行う。Codex の未コミット作業（`feat/landscape-trial-100m`）には混ぜない。
- ユーザーへの報告は日本語で、初心者向けに書く。見た目を直したら、同じ視点の画像を並べて見せてから「直った」と言う。

## ユーザーが決めたこと

- **進め方：空撮で確認し、あとはスクリプトで機械的に設置する**（ユーザー：「空撮で確認し、あとは機械的にスクリプトで設置するようなイメージ」）。人が一か所ずつ見て直すやり方はとらない。Codex の S1 のような、距離10mごとの画像確認や、区間ごとの手調整（802枚の画像、67区分の作業表）はしない。人の目で見るのは、空中写真との比較と AC での試走だけにする。直すときは、地点ごとの手直しではなく、規則（しきい値・密度など）を直して全域を作り直す。
- **使用量（AI の利用率）を節約する。** ユーザー：「あなた全てに任せてしまうと、利用率がいくらあっても足りなくなる」「機械的に設置可能な状態であれば、スクリプト組んでいっきに実装する感じがベスト」。そのため、次のようにする。
  - スクリプトは一度組めば、**コマンド1回で全域を一気に作れる**ようにする。木のパターン作り、空中写真からの判定、配置、AC 用ファイルの書き出しまで含める。
  - AI が画像を何百枚も見る確認や、たくさんのサブエージェントを動かす進め方はしない。AI の確認は、要所の数枚の画像と数値チェックだけにする。
  - 直すときは、設定値を変えてスクリプトをもう一度走らせるだけで済む作りにする。
- **コース沿いの木も、できるだけ機械的に植える。ただし、コース沿いの壁・橋・その他の施設はリアルに仕上げたい**（ユーザー：「コース沿いについては壁、橋、その他施設などはリアルに仕上げてほしいので、考慮に入れておいてください」）。森の側では、次のことを守る。
  - 壁・擁壁・ガードレール・橋・トンネル坑口・建物・標識・バス停などを、木が貫いたり隠しすぎたりしない。施設の形（`*_features.csv`、`s5_bridges.json`、`s5_tunnels.json` などの記録）から、自動で木を植えない範囲を作る。
  - 擁壁の上や法面の上には植えてよい（現地でも木が生えている）。ただし、根元が壁の面より道路側に出ないようにする。
  - 施設を後でリアルにするとき、森を作り直さずに済むようにする。施設のまわりの「植えない範囲」は設定で変えられるようにし、スクリプトをもう一度走らせるだけで合わせられるようにする。
- 対象はマップ全体。
- 道路脇の木も新しい森に置き換え、切れ目なくつなぐ。
- 品質は S1 の木並み。おもちゃの木は不可。
- 複数パターンの木で置き換える。
- 空撮と比較して仕上げる。
- 空からも、運転席からも、歩いても森に見えること。

## Claude が決めたこと（ユーザーは変更できる）

1. **表示の方法は CSP の木の機能。** まず小さな試しで、木のパッケージ（`.mesh` 形式）を自分で作れるかを確かめる。既存の例のファイルを読み解いて作る。作れなかった場合の代わりは、別の kn5（`yabitsu_forest*.kn5`）に木を入れる方法。この場合は kn5 の LOD 距離（各メッシュの表示開始・終了距離）を使い、近・中・遠の3段階で切り替える。どちらの方法でも、既存の kn5 は作り直さない。
2. **木の形は S1 の作り方を出発点にする。** Sapling の枝分かれ原型（`assets/landscape/broadleaf_prototypes_v2.json`）と、写真から作った葉のテクスチャを使う。杉・檜は、まっすぐな幹と段になった枝葉の専用の形にする。素材のライセンスは README に記録する（CC0 など、再配布できるものだけを使う）。
3. **近くの木ほど細かくする。** 歩いて触れる距離では、幹の質感・枝・葉の重なりまで作る。遠くでは軽い形に切り替える。遠くの形も、上から見た色・ムラ・影を近くの木とそろえる。
4. **木の密度は、空から地面がほとんど透けない程度。** 植林地なら本物の植林のように並びが揃い、自然林ならばらける。全域で本数をどう段階分けするか（例：道路や歩ける範囲は実際の密度、遠い山は大きめの木を少なめ）は、作る人が性能を見て決める。
5. **森の地面（落ち葉・下草・シダ）は、道路や歩ける範囲を中心に入れる。** 方法は CSP の草の機能か、木と同じ仕組みの低木・下草。
6. **最初に AC で試作を見てもらう。** 試作は、木のパターン全種類を S1 付近の限られた範囲に植えたもの。運転席と、降りて歩いた視点の両方で見られるようにする。ユーザーが「S1 の木並み」と OK を出してから全域に広げる。試作の前の検証は、壊れていないことの確認だけにとどめる。
7. **全域に広げた後の確認。** 上空からの比較画像（空中写真｜新しい森）を数か所、運転席の画像を数か所作る。その後、ユーザーに AC で走ってもらう。FPS はユーザーの PC で見てもらう。目安は、今の普通のレイアウトから大きく下がらないこと。
8. **森は普通の16レイアウト全部に入れる。** 一度入れれば、全レイアウトで同じ森になる。

9. **Codex の未コミット素材の再利用。** Codex は作業を止めている（ユーザーが中止した）。新しいブランチには、必要なもの（`assets/landscape/broadleaf_prototypes_v2.json`、`branchleaves_cc0.png` と README、木の形を作るコードの必要部分）だけを写して取り込む。それ以外の Codex の作業は未コミットのまま残す。`content/tracks/yabitsu/extension/ext_config.ini` はこの作業が持つ。
10. **木を植えない道。** 対象は、ゲームの中に作った道すべて（本線、分岐路、バリケードの先の分岐路の部分）と、OSM の車道のうち地形の範囲にあるもの。ただし OSM の `highway=track`（林道・作業道）は、空中写真で道が見える場所だけ空ける。空中写真の判定で森にならない場所には、もともと木を植えない。範囲を変えても、スクリプトを再実行するだけで済む。
11. **CSP があることを前提にする**（ユーザー回答「CSPありきでいいです」）。CSP なしの人には新しい森が出ず、古い板の木が残るが、それでよい。公開 zip（`scripts/package_release.py`）を次に作るときは、Codex の試作ファイル（`yabitsu_s1_landscape_test.kn5` 1.6 GB と `s1_landscape_*`）を入れないようにする。
12. **Codex の S1 景観確認レイアウトには森を入れない。** CSP のレイアウトごとの設定を使って分ける。

## 作る人に任せること

- 木のパターンの数（各樹種で最低2〜3）、各 LOD の三角形数、切り替え距離。
- 空中写真から森・樹種を判定する具体的な方法（色・きめ・明るさのしきい値など）。判定結果は地図画像にして、ユーザーが見られるようにする。
- 一覧ファイルの分け方（区間ごと・タイルごと）、CSP 側の細かい設定値。
- 古い板の木を隠す設定の書き方。
- 作業手順の細かい分け方。ただし、AC 試作をユーザーに見せる時点は早めにする。
