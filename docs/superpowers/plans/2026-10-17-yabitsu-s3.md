# S3（名古木 → 蓑毛）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 国道246号の名古木交差点から蓑毛までを、今の道（蓑毛 → 峠）の下に1本につなぎ、交差点の半径 200m を地図どおりの道と建物で作り、ヤビツ方面以外の道を工事中の柵で封鎖し、S3・全線のレイアウトを足す。S1・S2 は変えない。

**Architecture:** S3 の本線は S1・S2 と同じ「中心線＋横断面の帯」で作る（`config.SECTIONS` の先頭に s3）。交差点の半径 200m（「町の範囲」）だけは帯を使わず、新しい `yabitsu/town.py` で OSM の道の線から多角形（車道・歩道・縁石）を作り、なめらかにした地面の高さ（`yabitsu/town_ground.py`、県道70号の上では本線の路面の高さそのもの）にかぶせる。本線の帯は町の範囲の外から始める。走れる範囲は「県道70号＋交差点の中＋そのまわりの歩道」で、境に見えない壁、横道の入口に工事中の柵を置く。建物は地理院の外周線＋OSM から形を取り、町の範囲は `data/manual/s3_buildings.json` に Claude が Street View で1棟ずつ高さ・屋根・色・看板を書く。町の範囲の部品は別の kn5（`yabitsu_nagoki.kn5`）に入れる。最初に交差点だけで試作し（Task 1〜9 のあと Task 10 でユーザーが走る）、OK をもらってから S3 全体の道ぞいを仕上げる。

**Tech Stack:** Python 3.12（uv）、numpy・scipy・shapely・pyproj・Pillow、pytest、Blender 5.2（確認用の描画だけ）、Playwright（Street View の画像取得）、自前の kn5 書き出し（`yabitsu/kn5.py`）

**Spec:** `docs/superpowers/specs/2026-10-17-yabitsu-s3-design.md`（全体構成は `2026-10-17-yabitsu-s1-design.md`・`2026-10-17-yabitsu-s2-design.md`）

## Global Constraints

- `content/tracks/nanohanadai` には書き込まない（書き込みは必ず `config.assert_writable` を通す）
- 座標は EPSG:6677、原点はヤビツ峠（`geo.py`）。スタート・ピット・計測位置・駐車場・広場・建物・柵・路面の表示は緯度経度で決め、通しの距離 s には頼らない
- `data/manual/s1_*`・`s2_*` は書き換えない（S2 の家を `houses.py` へ移す作り替えでも、`s2_minoge.json` の中身は変えない）。区間の表の距離は「その区間の始点からの距離」
- S1・S2 の道：蓑毛のつなぎ目（S2 の始点）から 30m より先は、中心の位置・高さとも今と 0.1m 以内。既存4レイアウトのスタート・ピット・計測位置、菜の花台・峠・蓑毛まわりは今と同じ場所
- 交差点の中心＝OSM node 293317044（35.3796436, 139.2358251）。町の範囲＝そこから半径 200m
- 封鎖：ヤビツ方面（県道70号）以外の道は、交差点の入口（横断歩道の外側）に工事中の柵＋見えない壁。一歩も入れない。200m 以内の道と建物は景色として作る
- 看板は位置・大きさ・色と店名の文字まで。会社のロゴの絵は入れない
- 信号機は固定の灯火（車用は青、歩行者用は赤）。電線は張らない
- ゲーム用ファイルは `scripts.make_kn5` で直接書く（ksEditor は使わない）。出典表記は `CREDITS`（`出典：国土地理院（標高タイル・シームレス空中写真・基盤地図情報）／© OpenStreetMap contributors (ODbL)`）
- リポジトリのファイルは LF で書く（Python の `write_text` は `newline="\n"` を付ける）。AC 用の ini・json は `acdata.write_text`（CRLF）のまま
- スクリプトは `uv run python -m scripts.<name>`、テストは `uv run pytest -q`
- 木・森の見た目は作り込まない（全区間ができてからの仕上げ）。ただし木が道・建物・町の範囲にかぶらないようにはする
- ユーザーに手作業を渡さない。ユーザーの番は「走って確かめる」「Street View で地点を選ぶ・結果を見て OK を出す」だけ

## Review Focus

1. **本線の道を探す処理が横道を拾う**：交差点のまわりは住宅地の細い道が多い。OSM の道で最短経路を探すと、県道70号ではなく住宅地の道を通ることがある → 経路探しに使う道は「ref が 70 か、ref・name に 秦野清川線／県道70号 を含む道」だけに絞る（Task 2 のテスト）
2. **町の範囲と本線の帯の境目の段差**：町の路面（多角形）と本線の帯は別々に作る。境目で高さがずれると、上りで突き上げる → 町の地面は本線の路面の近くでは本線の高さそのものにし、境目の両側 1m で高さの差 ≤ 0.02m を確かめる（Task 4・5 のテスト）
3. **走れる範囲の壁のすき間**：柵と見えない壁、本線の帯へ出る口の間にすき間があると、車が住宅地や店の敷地に出てしまう → 走れる範囲の外周が、本線の帯への口を除いて全部壁でふさがれていることを、外周の線で確かめる（Task 6 のテスト）
4. **建物が道や歩道にはみ出す**：地理院の外周線と OSM の建物の形は少しずれていて、歩道や車道にかかることがある → 車道・歩道と 0.3m 以上重なる建物は、その部分を削って置き、削れた量を一覧に出す（Task 7 のテスト）
5. **全線のレイアウトで別の区間の点を拾う**：全線（名古木 ⇄ 峠）のレイアウトでは、スタートとゴールが別の区間にある。1つの区間だけで探すと失敗し、全部の区間で探すと菜の花台のヘアピンで別の枝を拾う → 地点ごとに区間を書けるようにする（Task 8 のテスト）
