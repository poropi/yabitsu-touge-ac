# S5（札掛 → 宮ヶ瀬北原交差点）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 札掛から宮ヶ瀬北原交差点までの県道70号（約 11.7km）を S4 の先につなぎ、トンネル3か所・名前のある橋15か所・川・宮ヶ瀬湖・ゴールの交差点（半径 200m、名古木と同じ作り）を作り込み、S5 と全線のレイアウト4つを足す。S1〜S4 と今の12レイアウトは変えない。

**Architecture:** 本線は今まで通り「中心線＋横断面の帯」（`config.SECTIONS` の最後に s5、高さは `fit_sections(fixed=3, robust=True)` で S4 の後ろに1つずつつなぐ）。トンネルは新しい `yabitsu/tunnel.py`（OSM の tunnel way を本線の s の範囲にし、高さの合わせ・地形の削りから外し、筒・照明・坑口・表札のメッシュを作る）。名前のある橋は新しい `yabitsu/bridge_parts.py`（親柱と銘板、大きな橋の桁と橋脚。S5 の橋の下は地形を盛らない）。湖は `water.py` に湖面を足す。ゴールの交差点は `nagoki.py` を「交差点ごとの設定」で動くようにして使い回す（名古木の結果は変えない）。

**Tech Stack:** Python 3.12（uv）、numpy・scipy・shapely・pyproj・Pillow、pytest、Blender 5.2（確認用の描画）、Playwright（Street View）、自前の kn5 書き出し

**Spec:** `docs/superpowers/specs/2026-10-18-yabitsu-s5-design.md`（全体の決まりは S1〜S4 の設計書、S4 の作りは `docs/superpowers/plans/2026-10-18-yabitsu-s4.md`）

## Global Constraints

- `content/tracks/nanohanadai` には書き込まない（`config.assert_writable`）
- 座標は EPSG:6677、原点はヤビツ峠。地点はすべて緯度経度で決める
- `data/manual/s1_*`〜`s4_*` は書き換えない。S5 の表は `data/manual/s5_*`、交差点は `data/manual/s5_kitahara*.json`
- S1〜S4 の道：札掛のつなぎ目（`S4_END`）から 30m より手前は位置・高さとも今と 0.1m 以内。今の12レイアウトのスタート・ピット・計測位置は今と同じ。名古木の町（`yabitsu_nagoki.kn5` の中身）は変えない
- S5 の区間：`S4_END`（35.4651366, 139.2137214）→ `KITAHARA`（35.5187747, 139.2309644、OSM node 293598433）
- 高さ：`fit_sections(..., fixed=3, robust=True)`。トンネルの中は標高データを使わない（橋と同じく外して補う）
- ピットは計測の始まりより手前（S4 の最終レビュー）。分かれ道は柵の先 200m、柵・入口の壁・奥の壁は別の部品。水面は下流へ下がり、路面に出ない
- kn5：`yabitsu_s5.kn5`（`config.S5_GROUP`）、`yabitsu_kitahara.kn5`（`config.KITAHARA_GROUP`）。全部のレイアウトが全部の kn5 を読む
- 看板・表札・銘板は文字と色まで（ロゴなし）。電柱・電線・木の作り込み・路面の文字は作らない
- ファイルは LF、AC 用 ini・json は `acdata.write_text`。テストは `uv run pytest -q`
- 長い作り直し（terrain・manifest・Blender）は `timeout` と `faulthandler.dump_traceback_later` をつけて流す（止まったまま待たない）
- ユーザーへの報告は日本語。直したところは直す前・直したあと・ストリートビューを並べて見せる

## Review Focus

1. **トンネルの上の地形に穴があく・坑口で地形が道にかぶる**：トンネルの範囲は地形を削らないので、坑口の前後で「削る／削らない」が切り替わる所に段差・すき間ができやすい → Task 3 のテスト `test_portal_has_no_gap_between_terrain_and_portal_face`
2. **トンネルの中で、山の地形の三角形が路面・壁の中に入りこむ**（山が低い所・浅いトンネル）→ Task 3 のテスト `test_terrain_stays_above_the_tunnel_roof`（土かぶりが薄ければ、その所の地形を屋根の上まで持ち上げる）
3. **S5 の大きな橋の下で地形を盛らなくすると、S1〜S4 の橋の下も変わる** → Task 4 のテスト `test_bridges_before_s5_keep_todays_terrain`（S4 までの橋の下の地形は今と同じ）
4. **名古木の作りを交差点ごとの設定にしたとき、名古木の結果が変わる** → Task 6 のテスト `test_nagoki_town_unchanged_after_generalising`（車道・歩道・走れる範囲・封鎖の線の面積と位置が今と同じ）
5. **湖面が橋・道・川原の上に出る、湖面と川の水面が段違いになる** → Task 5 のテスト `test_lake_is_below_every_road_and_bridge`
