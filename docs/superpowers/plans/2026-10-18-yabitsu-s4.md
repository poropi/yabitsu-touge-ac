# S4（ヤビツ峠 → 札掛）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ヤビツ峠の先（`S1_END`）から札掛橋の北 250m までの県道70号を、今の道（名古木 → 峠）に段差なくつなぎ、コースから 200m 以内の道・橋・分かれ道（柵の先 200m まで）・川・沢・滝・建物・道ぞいの物をすべて作り、S4 のレイアウト4つを足す。S1〜S3 と今の8レイアウトの走り方は変えない。

**Architecture:** S4 の本線は S1〜S3 と同じ「中心線＋横断面の帯」（`config.SECTIONS` の最後に s4）。高さの合わせ直しは、受け入れ済みの区間（s3・s2・s1）を今のまま固定し、S4 の始まりだけを S1 の終わりにすりつける（`elevation.fit_sections(..., fixed=3)`）。分かれ道は今の `side_roads.Stub` を 200m まで伸ばし、奥の終わりにも見えない壁。川は新しい `yabitsu/water.py`（OSM の川の線 → 下流へ下がる水面＋川原、地形に川の溝を彫る）。S4 の部品は場所で分けて `yabitsu_s4.kn5` に入れ、全部のレイアウトがそれを読む。

**Tech Stack:** Python 3.12（uv）、numpy・scipy・shapely・pyproj・Pillow、pytest、Blender 5.2（確認用の描画だけ）、Playwright（Street View の画像取得）、自前の kn5 書き出し（`yabitsu/kn5.py`）

**Spec:** `docs/superpowers/specs/2026-10-18-yabitsu-s4-design.md`（全体の決まりは S1〜S3 の設計書 `docs/superpowers/specs/2026-10-17-yabitsu-s{1,2,3}-design.md`）

## Global Constraints

- `content/tracks/nanohanadai` には書き込まない（書き込みは必ず `config.assert_writable` を通す）
- 座標は EPSG:6677、原点はヤビツ峠（`geo.py`）。区間の端・スタート・ピット・計測位置・駐車場・建物・柵・川の目印は緯度経度で決める
- `data/manual/s1_*`・`s2_*`・`s3_*` は書き換えない。S4 の表は `data/manual/s4_*`。区間の表の距離は「その区間の始点からの距離」
- S1〜S3 の道：峠のつなぎ目（`S1_END`）から 30m より手前は、中心の位置・高さとも今と 0.1m 以内。今の8レイアウトのスタート・ピット・計測位置は今と同じ
- S4 の区間：`S1_END`（35.4282221, 139.2190026）→ `S4_END`（35.4651366, 139.2137214。札掛橋 way 131561915 の北の端から県道70号に沿って 250m）
- 分かれ道（S4。OSM の `highway=track` の林道も含む）は入口から 200m（短ければ道の終わり）まで作る。入口に工事中の柵＋見えない壁（本線・歩道・横断歩道から `CLEAR_M`=1.0m 離す）、奥の終わりに見えない壁。柵・入口の見えない壁・奥の見えない壁は、それぞれ別のメッシュ
- 川・沢は、コースから 200m 以内の OSM の `waterway=river|stream`。水面は下流へ向かって下がる（上がらない）。水面・川原は本線と分かれ道の路面の上に出ない
- 看板は店名の文字と色まで（ロゴなし）。電柱・電線・木の作り込み・路面の文字は作らない
- S4 の部品は `yabitsu_s4.kn5`（`config.S4_GROUP`）。全部のレイアウトの `models_*.ini` がこれを読む
- ゲーム用ファイルは `scripts.make_kn5` で直接書く。出典表記は今の `CREDITS` のまま
- リポジトリのファイルは LF（`write_text(..., newline="\n")`）。AC 用の ini・json は `acdata.write_text`（CRLF）
- スクリプトは `uv run python -m scripts.<name>`、テストは `uv run pytest -q`
- ユーザーへの報告は日本語。直したところは、直す前・直したあと・ストリートビューを並べた画像で見せる

## Review Focus

1. **峠のつなぎ目で S1 下りのスタート列・ホットラップの点が動く**：S1 下り・全線 下りのスタート列（35.42788, 139.21926）は `S1_END` の約 40m 手前で、中心線のなめらか化（`smooth_xy` の sigma 4m）がつなぎ目の向こうの S4 の点に引っぱられうる → Task 2 で、今の8レイアウトのスタート・ピット・計測位置が 0.1m 以内であることを、今のテスト（`test_s1_layout_objects_unchanged` ほか）で確かめる
2. **道の下を沢がくぐる所（橋でない所、暗渠）**：OSM の沢の線が橋の印のない所で本線を横切ると、水面が路面の上に描かれる → Task 5 のテスト `test_water_is_never_drawn_on_a_road`
3. **200m の分かれ道が、本線にまた近づく・ほかの分かれ道や川と重なる**：長くすると、つづら折りで本線へ戻る道や、2本の分かれ道が同じ所に出る道がある → Task 4 のテスト `test_long_branch_stops_before_touching_the_main_road_again`
4. **S4 の部品を場所で分けるとき、つなぎ目をまたぐ部品（地形のかたまり、まとめた建物）が両方・どちらにも入らない**：→ Task 7 のテスト `test_split_puts_every_mesh_in_exactly_one_group`
5. **地形・川・建物が S4 の路面や分かれ道の上に出る**：→ Task 9 で `track_check` に「地面が路面の 10cm 以内」の数（本線と分かれ道）を足し、0 を確かめる
